User Story: As a Front-End System, I need a delete endpoint that rigorously protects pending and confirmed slots from being erased.

Specific Description: Create DELETE /api/psychologist/slots/{id}.

Data Integrity Check: Before executing the delete command, query the slot's current status. If the status is tentative or confirmed, return a 422 Unprocessable Entity or 403 Forbidden with an error message. Only execute the delete if status === 'available'.

DoD: The endpoint successfully deletes available slots but rigidly rejects deletion attempts on actively booked or pending time blocks.
